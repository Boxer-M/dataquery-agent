# 文档工作台 v1

在现有数据问答工作台的侧栏打开「文档知识库」。选择 PDF 后，界面显示文件名和大小。点击「上传 PDF」开始提取。已有文档时，可以上传新文档，也可以替换当前文档的 PDF。上传回执提供 Document ID、导入版本、页数与状态。

页选择器显示实际页码、提取方法和每页状态。左侧保留原始提取，右侧用于编辑人工修订文本。OCR 行级位置和置信度来自提取 API，展开后可逐条查看。空白页标为「空白页」。部分提取和失败会显示 API 提供的错误标识，并影响审核资格。

编辑文档标题、逐页文本和审核依据后，点击「提交审核」。接口返回审核版本后，确认将审核后的标题及文本发送给 Gemini，再点击「发布到知识库」。发布成功时显示知识版本。重复发布同一版本会显示索引复用。索引失败时保留最后一次确认的审核状态，可用同一回执重试。

「在聊天中询问此文档」会把文档标题写入现有聊天输入框。可补充页码、扫描页标题或要引用的段落，再发送。现有 Knowledge Agent 按知识库权限检索并返回引用。标题是检索线索，问答接口没有按 Document ID 强制筛选的能力。

## 实现与边界

抽屉按需加载，当前 PDF、草稿及上传回执仅在页面内存中保留。关闭抽屉后仍可继续当前审核。刷新整个浏览器页面会清空这部分界面状态，已提交的资料继续保存在 API 暂存区。初次上传支持 10 MiB、40 页以内的 PDF。带上文件后需要由用户显式提交，网络错误不会自动重新发送创建请求。若上传已落盘而回执丢失，当前 API 没有文档列表可找回未知的 Document ID。

文档请求沿用已有同源代理的精确路径和 HTTP 方法白名单。浏览器只发送工作台标识和请求内容，Bearer 由代理添加。Owner、签名与发布版本校验在服务端执行。替换文件后，旧知识版本可能继续参与检索，直至新版本成功发布。

## 复现

保持 Vite 工作台在 5173 端口运行。浏览器评测用隔离暂存区启动环回 API，占用 8000 端口，运行前先结束当前占用该端口的本地服务。评测使用授权合成 PDF，完成后撤下测试文档。

```sh
WORKSPACE_DOCUMENT_UI_E2E=1 WORKSPACE_DOCUMENT_SCREENSHOTS=/tmp/dataquery-document-ui \
  PYTHONPATH=src .venv/bin/python tests/evaluate_integrated_browser.py
npm --prefix frontend test
npm --prefix frontend run build
```

## 真实 Chrome 验收

通过工作台上传原生文本 PDF 和扫描合成 PDF。扫描样例包含三个页面，分别为原生文本、OCR 和空白页。第 2 页修改后提交真实审核。第一次发布模拟索引超时，界面保留「已审核」。随后实际生成一批 Gemini 文档向量并发布到 PostgreSQL，第二次发布返回同一版本并复用索引。

从文档入口草拟聊天问题并发送后，真实 Knowledge Agent 返回第 2 页的 `Reviewed UI appendix: confirmed by human review.`。引用来自审核后修订文本，文件 Hash 与实际上传原件一致。替换为另一版本后，旧审核回执由后端拒绝，返回 `409 / stale_upload_version`。网络中断演练只发出一次上传请求，界面提示确认后手动重试。测试 PDF 已撤下。

同次 Chrome 验收通过现有问答、正式引用、澄清续问、月度和渠道图表、查询历史与 Trace。浏览器请求校验了 Bearer 隔离，生产构建扫描未匹配本地 Bearer 与审核密钥。
