## 批次A：完整DWD + 必要公共DIM（一个功能PR）

输入：已接入的同一SQL Shed七表快照、已批准8项口径、既有order_item_fact及其报告。

- [ ] 固化源快照和模型依赖清单，将现有DWD中的业务/质量SQL移入版本化文件，保证原14列与结果不变；Python保留事务/执行编排。36项既有测试持续通过。
- [ ] 一起建设dim.customer/product/category/date/channel，明确定义当前属性、NULL和父品类规则；不复制姓名/email到通用维度。
- [ ] 一起建设order_fact、payment_attempt_fact、return_record_fact，完整保留源记录和业务异常标识；只读复用既有order_item_fact，不删除/覆盖它。
- [ ] 实现一个批量入口和拓扑计划，支持相同构建键校验复用、全批事务、并发锁、目标冲突拒绝和脱敏报告；不引入新框架。
- [ ] 隔离PostgreSQL集成测试正式纳管：批次失败回滚、已有表冲突、重复执行、并发和原明细不被写入；不重跑会删除个人表的临时脚本。
- [ ] 按QUALITY_AND_ACCEPTANCE逐主题验证四事实、五维度、原8项GT、源数据未变；检查SQL/报告无密钥与PII。
- [ ] 完整验收后统一Commit/Push并创建一个“完整DWD及公共维度”功能PR，包含当前已有明细实现及本轮正式设计，不自动Merge。未全部通过不宣称完整DWD已完成。

验收产物：9个可用事实/维度逻辑对象（4事实含原1张、5维度）、依赖清单、全部SQL、隔离集成测试、真实主题报告、明确未支持事项。扩展指标可先完成参考SQL，但尚无DWS时不能把planned_summary标成existing。

- [ ] 绑定同源DWD/DIM发布，一次建设6类日级DWS、3个普通ADS视图，不提前持久化重复月表。
- [ ] 对22项扩展指标逐项实现独立ODS GT SQL和边界测试；可用性只对真正通过的指标升级，不强迫unsupported产生数值。
- [ ] 证明月度/渠道/品类的可加性、账户跨期去重、支付尝试粒度、cohort按同as_of汇总、源异常保留和零分母NULL。
- [ ] 验收数据集可由纯SQL独立使用；ADS仅消费视图，不拥有写事实的旁路；完成快照清单与失败恢复策略。

退出条件：标准指标有实际路由能力矩阵和数据血缘，原8项保持定义；DWS/ADS不是空表或重复无用途汇总；数仓可在没有Agent时单独构建、核对和分析。
